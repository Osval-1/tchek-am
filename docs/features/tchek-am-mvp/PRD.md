# Product Requirements Document: Tchek-Am MVP (WhatsApp scam check and report bot)

> Generated by /to-prd. Update this file as the feature evolves.
> Version 1.0, 23 Nov 2026. Decisions: [../../ADR.md](../../ADR.md) (ADR-001 to ADR-013). Glossary: [../../CONTEXT.md](../../CONTEXT.md). Background: [../../prd.md](../../prd.md), [../../architecture.md](../../architecture.md), [../../idea-brief.md](../../idea-brief.md).

## Problem Statement
Most online selling in Cameroon happens in WhatsApp groups and statuses, and buyers pay upfront by MTN MoMo or Orange Money. Those payments offer no buyer protection. The most common scam: the buyer pays an advance or the full price, and the seller disappears. Buyers have no quick, local way to check a seller before paying.
- Ghana and Nigeria have scam-number databases, but nothing comparable exists in Cameroon.
- Truecaller is not built for local languages, MoMo-specific scams or reused product photos.

Those platforms also have gaps we can fill: none publishes an appeal process or makes old reports lose weight, both of which matter in a market where operators recycle numbers.

## Solution
**Tchek-Am** ("check am before you pay") is a WhatsApp bot in French, English and Cameroonian Pidgin. It does four things.
1. **Checks** a seller's number, product photo or message and returns a factual status band:
   - 🟢 no reports
   - 🟡 waiting for review
   - 🟠 reviewed, below the red threshold
   - 🔴 high risk
2. **Takes scam reports** from victims. They send screenshots and voice notes, the AI extracts the details, the victim confirms them, and the founder reviews every report before it affects any band.
3. **Detects reused product photos.** It matches photos against its own database (fed by bot submissions and silent **group listening** in consenting partner groups), then searches the web.
4. **Handles appeals,** including a path for recycled numbers.

Nothing reaches the public without human review. We never call anyone a "scammer", and reports lose weight over time.

Channel: WaSender for the pilot, behind an adapter so we can move to Meta's official Cloud API. Stack: Django + Postgres/pgvector on Render (Frankfurt), DeepSeek through OpenRouter for extraction and classification, OpenRouter Whisper Large V3 for voice notes, SerpAPI for web image search.

## User Stories
**Buyer**
- As a buyer, I want to send a seller's number in any format, and get a status band, the date of the last report and masked linked names, so that I can decide whether to pay.
- As a buyer, I want to forward a product photo and learn whether it has been posted by other numbers or appears in online catalogues, so that I can spot stolen photos.
- As a buyer, I want to paste a seller's message and see the red flags it contains, explained in plain language, so that I can recognise pressure tactics.
- As a buyer, I want the bot in French, English or Pidgin, with numbered menus, so that it's easy to use on any phone.

**Victim / reporter**
- As a victim, I want to send screenshots and a voice note and have the bot fill in the details for me, so that reporting takes under 5 minutes.
- As a victim, I want to see and correct what the AI extracted before I submit, so that my report is accurate.
- As a victim, I want my identity never to be shown to anyone except the moderator, so that I'm safe from retaliation.
- As a victim, I want to be told the outcome of my report and where else to get help (operator, police, ANTIC), so that I know what happens next.

**Reported number owner**
- As someone whose number has been reported, I want to appeal from that number with my side and evidence, so that wrong reports can be corrected.
- As the new owner of a recycled number, I want to say when I got the number, so that reports from before then are cleared quickly.

**Group member / admin**
- As a partner group admin, I want to add the bot to my group with my consent recorded, so that product photos in my group are checked for reuse.
- As a group member, I want to message "STOP GROUP" so that my posts are deleted and no longer collected.

**Moderator (founder)**
- As the moderator, I want a priority queue with evidence, AI-extracted fields I can edit, tamper flags and linked reports side by side, so that I can approve, reject, request more info or merge quickly.
- As the moderator, I want every action and every evidence view logged, so that decisions can be accounted for.

## Acceptance Criteria
**Checks**
- [ ] Number check accepts `6XXXXXXXX`, `+2376XXXXXXXX`, `002376XXXXXXXX` (with or without spaces and dashes), shared contact cards and numbers inside forwarded text. It normalises them to E.164 and returns the operator.
- [ ] The number check answers within 5 s at p95. The photo check returns internal matches within 10 s at p95.
- [ ] Each band follows the rules exactly:
  - [ ] 🟢 means no reports at all, or only rejected ones.
  - [ ] 🟡 means pending reports only, and shows the count only.
  - [ ] 🟠 means 1–2 approved reports without payment proof, or any approved report aged 12–24 months.
  - [ ] 🔴 means ≥ 3 independent approved reporters, or 1 approved report with payment proof, **and** ≥ 1 approved report from the last 12 months.
- [ ] Reporters are independent only if they use different WhatsApp accounts, neither report names the other reporter's number, and they didn't submit near-identical evidence within minutes of each other. A unit test covers each condition.
- [ ] Approved reports older than 24 months don't count toward any public band.
- [ ] A red result based on a single report says "1 reviewed report with payment proof".
- [ ] Every 🟠/🔴 result shows the month and year of the last report, plus how to appeal.
- [ ] No result ever includes a reporter's number or identity, unreviewed report details, the source group of a sighting, or the words "scammer", "fraud" or "arnaqueur".
- [ ] Linked account names are masked (e.g. `JEAN-P*** M***`).

**Photo check**
- [ ] It finds near-duplicates after resizing, cropping (up to about 20%), recompression and WhatsApp's own compression.
- [ ] Web search runs after the first reply, and its result is sent as a follow-up message only when it finds matches.
- [ ] Web search respects the per-user daily cap and the global monthly cap, and always runs on images attached to reports.

**Message check**
- [ ] It returns a list of named red flags with explanations, never a verdict. Numbers and names found in the text are checked automatically.

**Reports**
- [ ] The report flow collects images and voice notes, extracts details with AI, shows them to the user to confirm or edit, records consent (including the false-report warning), and submits as `pending`.
- [ ] Voice notes are transcribed. If the transcript is unclear (no number or amount found), the bot asks the user to type the key details.
- [ ] Training use of voice notes has its own separate opt-in.
- [ ] A user can resume a draft report within 24 h. Drafts are deleted 7 days after the last activity.
- [ ] Reporters can submit at most N reports per day.
- [ ] Reporters with repeatedly rejected reports are down-weighted.
- [ ] Extraction gets the reported number right ≥ 95% of the time on the eval fixture set.
- [ ] The reporter is notified of the moderator's decision, along with next-step guidance.

**Moderation**
- [ ] Moderation supports Approve, Reject (with a reason), Need more info (the bot asks the reporter) and Merge.
- [ ] Every action writes a `ModerationDecision` and an `AuditLog` entry, and refreshes the affected bands.
- [ ] Evidence opens only through short-lived signed URLs after login with 2FA, and every view is audit-logged.

**Appeals**
- [ ] Appeals can only be started from the reported number itself.
- [ ] While an appeal is open, the check result shows "under appeal".
- [ ] The "new to me" path records the date the appellant got the number.

**Group listening**
- [ ] The bot leaves any group that has no consent record.
- [ ] In partner groups, it stores only image fingerprints and a thumbnail, the poster's number, the time and the group. It stores no message text, and discards non-product images.
- [ ] It never posts in the group and never messages members directly.
- [ ] "STOP GROUP" deletes the sender's sightings and stops collecting their posts.

**Channel**
- [ ] All WhatsApp I/O goes through `MessagingChannel`, and no other module imports WaSender code.
- [ ] The bot replies only to users who message first, never sends unsolicited messages, rate-limits replies and adds typing delays.
- [ ] All menus are numbered text.
- [ ] The backup number can be enabled with a config change.

**Webhook and retention**
- [ ] The webhook is authenticated, stores each event idempotently and returns 200 within about 100 ms. All processing is asynchronous.
- [ ] A nightly retention job enforces the ADR-013 schedule, logs each deletion and skips items under legal hold.

## Out of Scope
- Escrow or holding funds, and any payment flows (Idea 2; needs a licensed partner).
- Verified seller badges, ID checks, public seller profile pages, subscriptions (Phase 2).
- B2B API, scam-ring cluster views for partners, admin digests, ANTIC data sharing (Phase 3).
- A native mobile app. A public numeric risk score.
- Multiple moderators, roles, queue assignment.
- Storing group message text. Posting in groups.
- The Meta Cloud API implementation (only the adapter seam is in scope). The Google Cloud Vision provider.
- Fine-tuning our own Pidgin speech model (only collecting the opt-in corpus is in scope).
- Helping victims recover money (we only give guidance).

## Open Questions
- **Company registration:** on hold. It blocks the move to the Meta Cloud API and any revenue.
- **Legal review:**
  - cross-border transfer and processors under Law 2024/017;
  - group-listening data;
  - the defamation exposure of band wording;
  - the basis for the false-report warning (Cameroon's 2010 cybersecurity law?);
  - privacy notice and terms text.
- **To verify:**
  - WaSender's webhook authentication, media download, group events and its support for sending images and message types;
  - each operator's number-recycling rules;
  - SerpAPI pricing and limits.
- **Numbers to set:** reports per day per reporter, web-search caps (per user per day, global per month), check rate limit (draft: 30 a day).
- **Copy:** native-speaker review of the Pidgin message catalogue.
- **Possible pilot changes:** the CLIP threshold and pHash distance (draft ≤ 8) must be tuned on a labelled image set.

## Technical Notes
- **Architecture:** a modular Django monolith plus a Procrastinate worker on Postgres. Modules:
  - `messaging`: the `MessagingChannel` interface and `WaSenderChannel`
  - `groups`
  - `conversations`: per-user state machine and input router
  - `identifiers`
  - `checks`
  - `reports`
  - `ai`: OpenRouter client, versioned prompts, structured JSON output, evals
  - `speech`: the `SpeechToText` adapter with Groq
  - `imaging`: sha256, pHash, CLIP/pgvector, and the `WebImageSearch` adapter with SerpAPI
  - `moderation`
  - `reputation`: pure functions for bands, threshold, independence and decay, with thorough unit tests
  - `retention`
- **Domain model:** `User`, `Conversation`, `InboundEvent`, `PhoneNumber`, `AccountName`, `Image` (vector(512)), `ImageSighting`, `PartnerGroup`, `Report`, `Evidence` (kind includes `voice`, with transcript), `ReportSubject`, `ReportLink`, `ModerationDecision`, `Appeal`, `AuditLog` (append-only), `CheckLog`, `AICallLog`. Records need legal-hold flags. Bands are computed, and cached with time-based expiry.
- **AI:**
  - DeepSeek V4.1 Flash through OpenRouter for routing and message red flags.
  - The same DeepSeek model for screenshot extraction, with a strict JSON schema: numbers, account names, amounts, transaction IDs, dates, operator, product, summary, tamper observations.
  - Prompt caching on system prompts. `AICallLog` tracks cost.
  - Evals: 30–50 FR/EN/Pidgin fixtures.
- **Security:**
  - Evidence goes in a private R2 bucket (EU) with encryption at rest and signed URLs.
  - PII is kept in separate tables.
  - Moderator 2FA. Secrets in the platform secret store. Every evidence access is audit-logged.
- **Infrastructure:**
  - Render, Frankfurt: web service, worker, Postgres with pgvector.
  - Sentry.
  - Local development: uv, Docker Compose (Postgres+pgvector, MinIO), and a tunnel for the webhook.
- **Build order:**
  1. Skeleton, CI, and WaSender webhook echo through the adapter.
  2. Number check plus router and i18n.
  3. Report flow, extraction, speech, admin moderation.
  4. Reputation rules.
  5. Photo check and group listening.
  6. Message check, appeals, notifications, rate limits.
  7. Retention, audit, backups, monitoring. Then the pilot.
- **Migration later:** a `MetaCloudApiChannel` for the official API, and a `GoogleVisionWebDetectionProvider` for web image search. Both are adapter swaps with no schema change.
